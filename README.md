# 광남고 포털 (portal-main)

학생·교사가 **ID/비밀번호로 로그인**해서 아래 메뉴를 쓰는 통합 앱입니다.

| 메뉴 | 학생 | 교사 |
|---|---|---|
| ✨ 빛나다 · 🎨 동아리 · 📚 교과 · 🔬 심화탐구 | 프로그램을 골라 활동 내용·파일 제출, 수정, 교사 메모 확인 | 프로그램 만들기/마감, 제출자료를 **학년도·프로그램·학년·반·검색어**로 필터, 목록/학생별 보기, CSV 내보내기, 메모 남기기 |
| 🕘 출석 (방과후·야간자율) | 내가 속한 반에서 **출석하기**(4자리 코드)·**나의 출결** | 출석체크(오늘 출석부에서 체크인 코드 띄우기·직접 체크) · 📊통계 · ⚙️반 관리(+ 새 반, 요일·교시·명단) |
| 📊 성적확인 | 내 성적 (record 앱 화면 이식) | 모든 학생 검색·조회 |
| 🧑‍🎓 학생별 모아보기 | – | 한 학생의 활동자료 전체 + 출결 요약 + 성적 바로가기 |

- Firebase 프로젝트는 **record 앱과 같은 `record-99cf0`** 를 씁니다. 성적은 기존 `students/{학번}/scores` 를 그대로 읽습니다.
- 새 데이터는 `users/`(계정 프로필)와 `portal/`(프로그램·제출·출결) 아래에 저장됩니다.
- 첨부 파일은 Apps Script 소유자의 Google Drive `스쿨포털_제출자료/학년도/구분/프로그램/학번_이름/` 에 **공유 없이** 저장되고, 앱이 로그인 토큰을 확인한 뒤에만 내려줍니다. (학생은 본인 파일만, 교사는 전체)

## 로그인 방식

- 학생 ID = 학번, 교사 ID = 영문/숫자 (예: `t_kim`).
- 내부적으로 Firebase Authentication 이메일/비밀번호 계정(`ID@gnhs-portal.app`)을 씁니다. 실제로 메일이 발송되지는 않습니다.
- Firebase 최소 길이(6자) 때문에 비밀번호 앞에 `gn#` 을 붙여 저장하므로, 사용자는 **4자 이상**이면 됩니다.
- 계정은 관리자가 **구글 시트에서 일괄 생성**하고, 첫 로그인 때 본인 비밀번호로 바꾸도록 강제합니다.
- 비밀번호 분실 → 시트에서 해당 행 선택 후 `🔑 선택행 PW 초기화`.

## 시트 메뉴 (`🏫 스쿨포털`) — 관리자만 보임

```
🏫 스쿨포털
  🔥Firebase 동기화
  ──────────
  🟰Record앱과 명단대조
  ──────────
  ⚙️관리자 도구 ▸ 🔑 선택행 PW 초기화
                  🚷 선택행 제외 처리
                  ──────────
                  ✅교사별 자료보기
                  ❌자료 삭제
                  ──────────
                  🔅신학년 준비
```

| 메뉴 | 언제 쓰나 | 하는 일 |
|---|---|---|
| 🔥Firebase 동기화 | 시트를 고칠 때마다 | UID 없는 행은 계정 생성, 있는 행은 이름·학년·반·ID 갱신. **시트에서 행이 사라진 사람은 확인을 받고 잠급니다**(🚷 제외 처리와 같음). 잠긴 사람의 행을 UID 까지 다시 붙이면 잠금을 풉니다. 시트의 열 제목·서식도 알아서 갖춰 줍니다 |
| 🟰Record앱과 명단대조 | 명단이 맞는지 볼 때 | **아무것도 고치지 않고 보여만 줍니다.** 올해 학번 기준으로 한쪽에만 있는 학생을 목록으로 띄웁니다 |
| ⚙️ 🔑 선택행 PW 초기화 | 비밀번호를 잊었을 때 | 선택한 행의 비밀번호를 바꾸고, 다음 로그인 때 변경하도록 표시. **전원 초기화**는 2행부터 끝까지 선택하고 공통 비밀번호를 입력 |
| ⚙️ 🚷 선택행 제외 처리 | 전학·자퇴 학생, 전근·퇴직 교사 | 로그인 차단 + 학번을 연도 열에 보존하고 ID 비움 + 행을 `전출` 시트로 이동 |
| ⚙️ ✅교사별 자료보기 / ❌자료 삭제 | 교사가 학교를 떠난 뒤 | 프로그램·출석 반은 만든 교사만 지울 수 있어서, 떠난 교사의 자료를 관리자가 정리 |
| ⚙️ 🔅신학년 준비 | **2·3월에만**, 학번 바꾸기 전 | ① 3학년 자동 졸업 이관 ② 지금 학번을 `○○○○년` 열에 보관 ③ 현재 학년도 +1 |

**📚 빛나다·동아리·심화탐구·교과 = 반 + 과제**: 반(프로그램)은 이름·명단·(빛나다) 요일만 정해 한 번 만들고, 제출할 일이 생기면 반 안에서 `➕` 로
**과제**(과제명·안내·제출 기간·파일 첨부 허용)를 추가합니다. `📓자유 기록` 을 켠 반은 과제 없이도 학생이 수시로 올립니다(동아리 활동 기록 등).
학생 첫 화면의 빨간 숫자는 **진행 중인 과제** 중 아직 안 낸 개수입니다. 예전에 만든 반은 만든 선생님이 관리 화면을 열 때 새 구조로 옮겨집니다.

**🪧 공지**(교사 메뉴): 모든 교사의 공지를 봅니다. `⚙️ 관리` 에서 `+ 새 공지`, 수정·삭제는 **만든 교사만**(관리자는 시트 `❌자료 삭제` 로 강제 삭제).
공지 기간(시작일~종료일) 중에는 **학생·교사 모두** 앱을 열 때 공지 창이 뜹니다 — 겹치는 공지는 한 창에 남은 기간이 짧은 순으로, 제목·기한·담당 교사와 `자세히보기`. 창 바깥을 누르면 닫힙니다.
창 아래 `오늘은 다시 뜨지 않기` 를 체크하면(학생·교사 모두) 그 기기에서 그날은 다시 안 뜹니다(그날 새 공지가 올라오면 다시 뜸).

**🍴 급식 · 📅 행사**(모두): 나이스(NEIS)에서 가져와 보여 주기만 합니다. 학교는 `Code.gs` 의 `NEIS_SCHOOL`(교육청 `Q10` · 학교 `7140225`)로 고정.
- 인증키는 **Apps Script 스크립트 속성 `NEIS_API_KEY`** 에만 둡니다(앱 코드·GitHub 에 없음). 앱 → Apps Script(`doPost` action `neis`, 로그인 필요) → NEIS.
- 급식은 월 단위(6시간), 학사일정은 학년도 단위(7일)로 브라우저에 저장해 두고, 다시 받기가 실패하면 지난 자료라도 보여 줍니다. Apps Script 도 같은 요청을 6시간 동안 캐시합니다.
- 어느 날 전부 "급식이 없습니다"만 나오면 **교육청 코드(Q10) 변경**을 먼저 의심하세요(2026-07 교육청 통합 뒤에도 Q10 유지 확인).

**🎓 졸업생**(교사 홈 카드): 졸업연도를 고르면 반별 사진첩, 사진을 누르면 `📞 전화`·`📩 문자`(번호가 없으면 "연락처가 없습니다."). 
**사진은 포털 저장소의 `images/` 폴더**에 있습니다(2026-09-19 record 저장소에서 옮겨 옴). 재학생 `images/{학번}.jpg`, 졸업생 `images/old/{졸업연도}_{3학년 학번}.jpg` — 신입생 사진 추가·졸업 처리 뒤 사진 옮기기도 이 폴더에서 하고, GitHub 에 올릴 때 `images/` 도 함께 올리세요. 전화번호는 재학 중 `계정` 시트 `전화번호` 열 값이 그대로 남습니다.

> **전학·자퇴·전근은 `🚷 선택행 제외 처리` 를 권장합니다.** 행을 직접 지워도 다음 `🔥Firebase 동기화` 때 확인창이 떠서 똑같이 잠글 수 있지만,
> 제외 처리는 동기화 없이 **즉시** 막히고, 누구를 뺄지 **직접 골라** 처리하므로 실수로 지운 행과 섞이지 않습니다.
> 어느 쪽이든 계정은 지우지 않고 잠그기만 하므로 지난 자료·출결은 교사 화면에 이름과 함께 남습니다.
> 실수로 잠갔다면 `전출` 시트의 그 행(UID 포함)을 계정 시트로 복사하고 ID 를 채운 뒤 동기화하면 되살아납니다.

## 설치 순서

### 1. Firebase 콘솔 (record-99cf0)
1. **Authentication → 로그인 방법 → 이메일/비밀번호 사용 설정**
2. (아직 규칙은 배포하지 마세요 — 5단계에서)

### 2. Apps Script (계정 관리 + 파일 저장)
1. 새 구글 스프레드시트 생성(예: `스쿨포털 관리`) → **확장 프로그램 → Apps Script**
2. `gas/Code.gs` 내용을 붙여넣기
3. 프로젝트 설정 → **"appsscript.json 매니페스트 파일 표시"** 체크 → `gas/appsscript.json` 내용으로 교체
4. `Code.gs` 상단 설정값 확인 (`ADMIN_EMAIL` 등)
5. **배포 → 새 배포 → 웹 앱**, 실행: **나**, 액세스 권한: **모든 사용자** → 권한 승인
6. 나온 웹 앱 URL을 `js/config.js` 의 `SCRIPT_URL` 에 붙여넣기

> 스크립트 소유자 계정이 Firebase 프로젝트의 **소유자(Owner)** 여야 계정 생성·DB 쓰기가 됩니다.

### 3. 계정 만들기
시트를 새로고침하면 `🏫 스쿨포털` 메뉴가 생깁니다.
1. 학생 행 입력: 구분=학생, ID=학번, 이름·학년·반·번호 (record 앱에서 명단을 복사해 붙여넣어도 됩니다)
2. 교사 행 추가: 구분=교사, ID=영문/숫자(예: `t_kim`), 이름
3. (선택) `🟰Record앱과 명단대조` → 빠뜨린 학생이 없는지 확인
4. `🔥Firebase 동기화` (수백 명도 한 번에, 시간 초과 시 다시 실행하면 이어서 처리)
   - 새 학년도에 반이 바뀌면 시트의 학년·반·번호만 고치고 다시 실행 → 정보만 갱신(비밀번호 유지)

`전화번호` 열(J열)에 적은 번호는 `🔥Firebase 동기화` 때 `users/{uid}/phone` 으로 올라가, 교사의 학생 정보 화면에 `📞 전화`·`📩 문자` 버튼이 생깁니다(번호가 없으면 버튼 없음). 하이픈은 있어도 되고, 시트가 앞의 0 을 떼어 내도 되살립니다.

초기 비밀번호 칸은 **비워 두면 공통 기본값 `1234`** 로 만들어집니다(`Code.gs` 의 `DEFAULT_PW`). 학생·교사는 첫 로그인 때 본인 비밀번호로 바꿔야 합니다.

### 4. 앱 배포
GitHub Pages 등에 이 폴더를 올립니다 (예: `https://puroome.github.io/portal/`).
Firebase 콘솔 → Authentication → 설정 → **승인된 도메인**에 `puroome.github.io` 가 있는지 확인하세요.

### 5. 보안 규칙 배포
규칙 파일이 두 개입니다.

| 파일 | 언제 | 내용 |
|---|---|---|
| `firebase/database.rules.json` | **지금 (2026-09-19 부터, record 앱을 학생이 더 쓰지 않음)** | 성적·사진은 본인·교사만, `graduates`·`admins` 등 record 앱 전용 경로는 아무도 못 읽음 |
| `firebase/database.rules.transition.json` | 예전 (record 앱과 함께 쓰던 동안) — 되돌릴 때만 | 기존 record 규칙(`students`·`info`·`graduates`·`admins` 공개 읽기) + 스쿨포털 보안 규칙(`users`·`portal`) |

- Realtime Database → 규칙에 해당 파일 내용을 붙여넣고 **게시**합니다. 바꾸기 전에 현재 규칙을 꼭 백업하세요.
- 기존 규칙이 이미 `.write: false` 이므로 record 앱의 성적 업로드 스크립트는 인증을 쓰고 있어 **수정할 필요가 없습니다.**
- 최종 규칙으로 바꾸면 record 앱(로그인 없이 성적을 읽는 방식)은 동작하지 않습니다.
- 최종 규칙 적용 후 DB에 남은 `students/{학번}/pw`(평문 비밀번호)는 지우는 것을 권장합니다.

규칙 요약:
- `users/` : 본인 것만 읽기, 교사는 전체 읽기, 쓰기는 Apps Script(관리자)만
- `students/{학번}/scores·name` : 본인 또는 교사만 읽기
- `portal/programs` : 로그인 사용자 읽기. 교사는 자기 이름(`createdByUid`)으로만 만들고, **만든 교사만** 수정·마감·삭제
- `portal/submissions/{프로그램}/{학번}` : 학생은 본인 것 읽기·쓰기(마감된 프로그램 제외). 교사 열람은 **공통 프로그램이면 모든 교사, `private`(🔒 담당자만)이면 만든 교사만**. 교사 메모는 만든 교사만
- `portal/att/codes` : 교사만 (학생은 코드를 DB에서 볼 수 없음)
- `portal/att/groups` : 로그인 사용자 읽기. **야간자율은 모든 교사, 방과후는 등록한 교사만** 만들고 고칠 수 있음
- `portal/att/sessions/{반}/{날짜}` : 그날 운영했다는 표시(코드를 열면 기록). 학생도 읽어 자기 출결을 셉니다
- `portal/att/records/{반}/{학번}/{날짜}` : 학생은 **명단에 있고 · 유효한 코드를 내고 · 아직 기록이 없을 때만** `출석`으로 한 번 기록 가능, 수정은 그 반을 다룰 수 있는 교사만

### 규칙 자동 테스트 (규칙을 고쳤을 때)
Java 21 과 `firebase-tools` 가 필요합니다. `firebase/test` 폴더에서:

npm run test:transition   (전환기 규칙)

실제 DB가 아닌 내 PC의 에뮬레이터에서만 돌아갑니다. 출력에 보이는 `permission_denied` 경고는 "막혀야 할 요청이 막혔다"는 뜻이므로 정상이며, 마지막 `fail 0` 이면 통과입니다.

## 프로그램별 교사 권한

| | 관리(수정·마감·삭제·교사 메모) | 제출자료 열람 |
|---|---|---|
| 🔒 담당자만 (교과·동아리 기본값) | 만든 교사 | 만든 교사 |
| 공통 (빛나다·심화탐구 기본값) | 만든 교사 | 모든 교사 |

- 프로그램 등록 창의 **"🔒 제출자료 열람도 담당 교사(나)만"** 체크로 정합니다.
- 학생별 모아보기에는 공통 프로그램 자료와 **내가 담당하는 비공개 프로그램 자료만** 보입니다. 출석·성적은 모든 교사가 봅니다.
- 첨부 파일도 같은 권한으로 Apps Script 가 확인한 뒤에만 내려줍니다.
- 담당 교사를 다른 교사로 넘기는 기능은 없습니다.

> **`🔒 담당자만` 은 "다른 교사에게만" 해당합니다.** 제출 파일은 Apps Script 를 배포한 계정의 드라이브에,
> 활동 내용 글은 Firebase 에 쌓이므로 **그 두 곳의 소유자(관리자)는 모든 자료를 볼 수 있습니다.**
> 앱 안에서는 규칙이 지켜지지만, 드라이브·Firebase 콘솔을 직접 열면 프로그램명·학번·이름·파일이 그대로 보입니다.
> 선생님들께 안내할 때는 "포털 안에서는 담당자만 본다" 로 설명하세요. 관리자 계정의 2단계 인증을 꼭 켜 두세요.

## ENGLISH (voca · novel 바로가기)

voca·novel 앱을 **새 탭에서 바로 여는 링크**입니다. 따로 설정할 것이 없습니다.

- 학생들은 원래 voca·novel을 쓰던 **자기 기기**로 포털에 들어오므로, 그 브라우저에 남아 있는 로그인으로 **기다림 없이** 바로 들어갑니다.
- 처음 쓰는 학생은 앱 주소로 직접 들어갔을 때와 똑같이 **Google 로그인 → 각 앱의 승인 절차**(voca 학생명단 · novel AllowedUsers)를 밟습니다.
- 주소는 `js/config.js` 의 `ENGLISH_APPS` 에서 바꿉니다.

> 예전에는 포털 Apps Script 가 1회용 로그인 토큰을 만들어 붙이는 "통합 로그인" 이었는데, 누를 때마다 1.5~4초씩 기다리게 해서
> 2026-09 에 없앴습니다. 그와 함께 `계정` 시트의 `학교 Google 계정` 열과 스크립트 속성 `SA_VOCA`·`SA_NOVEL` 도 더는 쓰지 않습니다.

## 출석 (방과후 · 야간자율)

| | 방과후 | 야간자율 |
|---|---|---|
| 교시 | 7교시 15:50~16:40 · 8교시 16:50~17:40 | 8교시 · 자율1 18:30~20:00 · 자율2 20:15~22:00 |
| 요일별 | 월(8) 화(8) 수(7·8) 목(7·8) 금(7) | 월~목(자율1·자율2) 금(8교시·자율1) |
| 반 등록·편집·출석체크 | **등록한 교사만** | **모든 교사** |

- **야간자율은 반 이름을 짓지 않습니다.** `학년`과 `교시`(8교시·자율1·자율2)만 고르면 이름(예: `1학년 자율1`)과 운영 요일이 자동으로 정해집니다 — 자율1 월~금 · 자율2 월~목 · 8교시 금요일. 같은 학년·교시 반이 이미 있으면 등록이 막힙니다.
- **야간자율 명단은 학년만 고르면 자동**입니다. 그 학년 `1반` 학생이 모두 들어간 상태로 나오고, 이름 버튼을 눌러 빼거나 다시 넣습니다. 대상 반은 `js/config.js` 의 `NIGHT_CLASS` 로 바꿉니다.
- **야간자율 목록은 8교시·자율1·자율2 묶음**으로 나뉘어, 학년별 반이 한눈에 보입니다. 방과후는 반 이름과 요일·교시를 직접 정합니다.
- 교사 화면은 프로그램 화면과 같은 구조입니다. 들어가면 **출석체크**가 기본이고, 오른쪽 위 **📊 통계 · ⚙️ 반 관리** 버튼으로 다른 화면에 갑니다(← 버튼으로 복귀). 방과후·야간자율은 **폴더 탭**으로 고릅니다.
  - **출석체크**: **오늘 운영하는 반만** 보이고, 출석체크도 **당일만** 됩니다. 다른 요일 반의 출석부를 열면(학생별 모아보기 등에서) "오늘은 운영하지 않는 날" 안내와 통계 바로가기만 나옵니다. 다른 요일 반은 반 관리·통계에서 봅니다.
  - **⚙️ 반 관리**: 반을 누르면 편집 창이 열리고, 오른쪽 위 **+ 새 반**으로 반을 만듭니다. 요일·교시를 고르고, 학년·반을 고르면 그 반 학생이 모두 켜진 채로 나옵니다. 버튼을 눌러 빼거나 넣습니다. 편집 창 아래에 운영 종료·삭제가 있습니다. `종료된 수업 포함` 으로 끝난 반도 볼 수 있습니다.
  - **📊 통계**: 처음에는 **오늘 하루**가 나오고, 날짜를 넓히면 그 기간을 합친 결과가 됩니다.
    - 야간자율은 **학년 버튼 → 번호·이름·교시 표**로 봅니다. 가로줄은 **그 기간에 실제 운영된 교시만** 나옵니다(예: 금요일 하루면 8교시·자율1).
    - 출석이 아닌 날이 있는 칸에 **`/`** 가 찍히고, 누르면 지각·조퇴·결석과 메모가 뜹니다. 기간이 하루가 아니면 **날짜별로** 나눠 보여 줍니다.
    - 방과후는 반을 골라 학생별 합계·출석률·CSV 를 봅니다.
- **야간자율은 그날 감독교사를 먼저 확인합니다.** 반에 들어가 `🙋 감독교사 확인`을 누른 교사가 그날 감독이 되고, 그전에는 체크인 코드·직접 체크가 모두 잠겨 있습니다. 감독이 정해지면 **그날은 다른 교사가 출석체크할 수 없습니다.** 잘못 눌렀다면 본인이 다시 눌러 내려놓을 수 있습니다. (방과후는 등록한 교사가 곧 담당이라 이 단계가 없습니다.)
- 출석부는 **오늘 날짜만** 다룹니다. `📋 체크인 코드`(30분 유효)를 학생에게 불러 주고, 기기가 없는 학생은 교사가 직접 누릅니다.
- 상태는 **출석·지각·조퇴·결석**이고, **체크인하지 않은 학생은 결석**입니다.
- 첫 교시 시작 **15분** 뒤 체크인은 자동으로 지각입니다 (`js/config.js` 의 `LATE_AFTER_MINUTES`).
- 학생 화면은 반마다 **출석하기 / 나의 출결** 둘뿐입니다.

## 학년도가 바뀔 때 (진급 · 졸업)

학생은 **UID 로 같은 사람**을 알아보고, 학번은 **학년도별 꼬리표**로 붙습니다.
학번은 해마다 다른 학생에게 다시 쓰이므로(올해 `10101` 신입생 ≠ 작년 `10101` 선배), 앱과 보안 규칙은
"**그 해에 그 학번이었던 학생**"인지까지 확인합니다. 선배는 자기 작년 자료를 보고, 같은 학번의 신입생은 볼 수 없습니다.

`계정` 시트
- `ID(학번/교사ID)` 열 = **올해 학번**. 오른쪽 아무 곳에 `2025년`, `2024년` … 헤더 열을 두고 그해 학번을 적습니다.
- 열은 **헤더 이름으로** 찾으므로 연도 열을 어디에 끼워도 됩니다(권장: 맨 오른쪽).
- `🔥Firebase 동기화` 를 실행하면 학생마다 `{ 학번: 학년도 }` 기록이 만들어집니다.

해마다 할 일 — **⚙️관리자 도구 → 🔅신학년 준비** 하나로 시작합니다

> **언제:** 그 학년도 활동이 모두 끝난 뒤(종업식 무렵)부터 새 학년도 첫 수업 전까지. **2월·3월에만 실행됩니다** — 다른 달에 누르면
> "새학년도 준비 기간이 아닙니다" 하고 멈춥니다. 실행하면 현재 학년도가 다음 해로 바뀌어 **지난 학년도 출결 체크인·자료 제출이 닫힙니다.**
> **시트의 학번을 새 학번으로 고치기 전에** 눌러야 합니다.

1. **🔅신학년 준비** — `○○○○학년도 활동이 모두 끝났나요?` 확인을 거친 뒤 세 가지를 한 번에 합니다.
   - ① **학번이 `3`으로 시작하는 학생을 모두 졸업시트로 자동 이관** (따로 고를 필요 없습니다)
   - ② 남은 학생의 지금 학번을 `○○○○년` 열에 보관
   - ③ 현재 학년도를 다음 해로 변경
   - 같은 학년도에 두 번 실행하면 다시 묻습니다. **시트의 ID(학번)는 이 단계에서 바뀌지 않습니다.**
2. **이제** 진급한 학생의 ID(새 학번)·학년·반·번호를 고치고, 신입생 행을 추가합니다.
3. **🔥Firebase 동기화** — 로그인 ID 가 새 학번으로 바뀌고, 비밀번호와 지난 자료는 그대로 이어집니다.
   전교생 학번이 한꺼번에 바뀌어도 충돌하지 않도록 임시 ID 를 거쳐 교체합니다.

예시 (2026학년도 → 2027학년도, 2학년 김철수)

| 단계 | ID 열 | `2026년` 열 | 현재 학년도 |
|---|---|---|---|
| 시작 | `20101` | (빈칸) | 2026 |
| 1. 🔅신학년 준비 | `20101` | **`20101`** | **2027** |
| 2. 손으로 수정 | **`30101`** | `20101` | 2027 |
| 3. ✅ 반영 | `30101` | `20101` | 2027 |

(같은 실행에서 3학년 `30101` 박선배는 `2027` 시트로 옮겨지고, 그의 `2026년` 열에 `30101` 이 남습니다.)

→ `users/{김철수}/sids = { 20101: 2026, 30101: 2027 }` 이 되어, 작년 자료는 계속 보이고 올해 `20101` 을 받은 후배와 섞이지 않습니다.

학기 중 전출입
- **전학·자퇴** → 그 행을 선택하고 `🚷 선택행 제외 처리`. 로그인이 막히고 행이 `전출` 시트로 옮겨집니다. **전근·퇴직 교사도 같은 메뉴**로 처리합니다.
- **전입** → 시트에 행을 추가하고 `🔥Firebase 동기화`. 초기 비밀번호를 비우면 `1234` 입니다.
  - ⚠ **전출 학생이 쓰던 학번(번호)은 그 학년도가 끝날 때까지 다시 쓰지 말고 뒷번호를 주세요.** 같은 해에 같은 학번을 두 사람이 쓰면
    "그 해에 그 학번이었던 학생" 판정이 겹쳐, 전입생이 전출 학생의 제출자료를 보게 됩니다. 다음 학년도부터는 얼마든지 재사용됩니다.
- `🟰Record앱과 명단대조` 로 두 명단이 어긋난 곳을 확인할 수 있습니다 (고치지는 않고 보여만 줍니다).

앱에서
- 학생: 지난 학년도 프로그램·출결이 **"○○○○학년도 / 지난 출결 · 보기만 가능"** 으로 함께 보입니다(수정·제출 불가).
- 교사: 통계와 학생별 모아보기가 그 해 학번으로 이름을 찾습니다. 야간자율 통계 기간이 두 학년도에 걸치면 **학년도별로 표를 나눕니다**.
- 성적(record 앱)은 지금 학번에 누적되므로 그대로입니다.

앱 계산 규칙 테스트: 프로젝트 폴더에서 `npm test` (출결 시간·연도별 학번·계정 시트 읽기)
