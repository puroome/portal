# 광남고 스쿨포털 (portal-main)

학생·교사가 **ID/비밀번호로 로그인**해서 아래 메뉴를 쓰는 통합 앱입니다.

| 메뉴 | 학생 | 교사 |
|---|---|---|
| ✨ 빛나다프로그램 · 🎨 동아리 · 📚 교과 · 🔬 심화탐구대회 | 프로그램을 골라 활동 내용·파일 제출, 수정, 교사 메모 확인 | 프로그램 만들기/마감, 제출자료를 **학년도·프로그램·학년·반·검색어**로 필터, 목록/학생별 보기, CSV 내보내기, 메모 남기기 |
| 🕘 출석 (방과후·야간자율) | 감독교사 화면의 **QR 스캔 또는 4자리 코드**로 체크인, 내 출결 기록 | 그룹(강좌·자습실) 만들기, 명단 관리, 코드·QR 띄우기, 실시간 출석부, 출/지/조/인/결 수정, 기간 통계·CSV |
| 📊 성적확인 | 내 성적 (record 앱 화면 이식) | 모든 학생 검색·조회 |
| 🧑‍🎓 학생별 모아보기 | – | 한 학생의 활동자료 전체 + 출결 요약 + 성적 바로가기 |

## 구조

```
index.html          화면 뼈대
css/style.css
js/config.js        ★ 설정 (Firebase, Apps Script URL, 카테고리, 출결 상태)
js/app.js           로그인 감시 · 라우터 · 홈 메뉴
js/auth.js          로그인 / 비밀번호 변경
js/programs.js      활동 자료 4종 (공용 엔진)
js/attendance.js    방과후 · 야간자율 출결
js/grades.js        성적 (record 앱 이식)
js/students.js      학생별 모아보기
js/drive.js         파일 업로드·열기 (Apps Script 경유)
gas/Code.gs         Apps Script: 계정 관리 메뉴 + 파일 저장 웹 앱
gas/appsscript.json
firebase/database.rules.json   ★ DB 보안 규칙
```

- Firebase 프로젝트는 **record 앱과 같은 `record-99cf0`** 를 씁니다. 성적은 기존 `students/{학번}/scores` 를 그대로 읽습니다.
- 새 데이터는 `users/`(계정 프로필)와 `portal/`(프로그램·제출·출결) 아래에 저장됩니다.
- 첨부 파일은 Apps Script 소유자의 Google Drive `스쿨포털_제출자료/학년도/구분/프로그램/학번_이름/` 에 **공유 없이** 저장되고, 앱이 로그인 토큰을 확인한 뒤에만 내려줍니다. (학생은 본인 파일만, 교사는 전체)

## 로그인 방식

- 학생 ID = 학번, 교사 ID = 영문/숫자 (예: `t_kim`).
- 내부적으로 Firebase Authentication 이메일/비밀번호 계정(`ID@gnhs-portal.app`)을 씁니다. 실제로 메일이 발송되지는 않습니다.
- Firebase 최소 길이(6자) 때문에 비밀번호 앞에 `gn#` 을 붙여 저장하므로, 사용자는 **4자 이상**이면 됩니다.
- 계정은 관리자가 **구글 시트에서 일괄 생성**하고, 첫 로그인 때 본인 비밀번호로 바꾸도록 강제합니다.
- 비밀번호 분실 → 시트에서 해당 행 선택 후 `🔑 선택한 행 비밀번호 초기화`.

## 설치 순서

### 1. Firebase 콘솔 (record-99cf0)
1. **Authentication → 로그인 방법 → 이메일/비밀번호 사용 설정**
2. (아직 규칙은 배포하지 마세요 — 5단계에서)

### 2. Apps Script (계정 관리 + 파일 저장)
1. 새 구글 스프레드시트 생성(예: `스쿨포털 관리`) → **확장 프로그램 → Apps Script**
2. `gas/Code.gs` 내용을 붙여넣기
3. 프로젝트 설정 → **"appsscript.json 매니페스트 파일 표시"** 체크 → `gas/appsscript.json` 내용으로 교체
4. `Code.gs` 상단 설정값 확인 (`ADMIN_EMAIL` 등)
5. **배포 → 새 배포 → 웹 앱**, 실행: **나**, 액세스 권한: **모든 사용자** → 권한 승인
6. 나온 웹 앱 URL을 `js/config.js` 의 `SCRIPT_URL` 에 붙여넣기

> 스크립트 소유자 계정이 Firebase 프로젝트의 **소유자(Owner)** 여야 계정 생성·DB 쓰기가 됩니다.

### 3. 계정 만들기
시트를 새로고침하면 `🏫 스쿨포털` 메뉴가 생깁니다.
1. `① 계정 시트 준비`
2. (선택) `record 학생 명단 가져오기` → record 앱의 학번·이름이 채워짐 (학년/반/번호는 학번에서 추정하니 확인)
3. (선택) `빈 초기 비밀번호를 record 비밀번호로 채우기` → 학생이 record 에서 쓰던 비밀번호를 그대로 사용
4. 교사 행 추가: 구분=교사, ID, 이름, 초기 비밀번호
5. `② 계정 생성 · 정보 반영` (수백 명도 한 번에, 시간 초과 시 다시 실행하면 이어서 처리)
   - 새 학년도에 반이 바뀌면 시트의 학년·반·번호만 고치고 다시 실행 → 정보만 갱신(비밀번호 유지)

### 4. 앱 배포
GitHub Pages 등에 이 폴더를 올립니다 (예: `https://puroome.github.io/portal/`).
Firebase 콘솔 → Authentication → 설정 → **승인된 도메인**에 `puroome.github.io` 가 있는지 확인하세요.

### 5. 보안 규칙 배포
규칙 파일이 두 개입니다.

| 파일 | 언제 | 내용 |
|---|---|---|
| `firebase/database.rules.transition.json` | **지금 (record 앱과 함께 쓰는 동안)** | 기존 record 규칙(`students`·`info`·`graduates`·`admins` 공개 읽기) 그대로 + 스쿨포털 보안 규칙(`users`·`portal`) |
| `firebase/database.rules.json` | record 앱을 완전히 끈 뒤 | 성적도 본인·교사만 읽기 가능하게 잠금 |

- Realtime Database → 규칙에 해당 파일 내용을 붙여넣고 **게시**합니다. 바꾸기 전에 현재 규칙을 꼭 백업하세요.
- 기존 규칙이 이미 `.write: false` 이므로 record 앱의 성적 업로드 스크립트는 인증을 쓰고 있어 **수정할 필요가 없습니다.**
- 최종 규칙으로 바꾸면 record 앱(로그인 없이 성적을 읽는 방식)은 동작하지 않습니다.
- 최종 규칙 적용 후 DB에 남은 `students/{학번}/pw`(평문 비밀번호)는 지우는 것을 권장합니다.

규칙 요약:
- `users/` : 본인 것만 읽기, 교사는 전체 읽기, 쓰기는 Apps Script(관리자)만
- `students/{학번}/scores·name` : 본인 또는 교사만 읽기
- `portal/programs` : 로그인 사용자 읽기. 교사는 자기 이름(`createdByUid`)으로만 만들고, **만든 교사만** 수정·마감·삭제
- `portal/submissions/{프로그램}/{학번}` : 학생은 본인 것 읽기·쓰기(마감된 프로그램 제외). 교사 열람은 **공통 프로그램이면 모든 교사, `private`(🔒 담당자만)이면 만든 교사만**. 교사 메모는 만든 교사만
- `portal/att/codes` : 교사만 (학생은 코드를 DB에서 볼 수 없음)
- `portal/att/records/{그룹}/{학번}/{날짜}` : 학생은 **명단에 있고 · 유효한 코드를 제출하고 · 아직 기록이 없을 때만** `출석`으로 한 번 기록 가능, 수정은 교사만

### 규칙 자동 테스트 (규칙을 고쳤을 때)
Java 21 과 `firebase-tools` 가 필요합니다. `firebase/test` 폴더에서:
```
npm install
npm test                  (최종 규칙)
npm run test:transition   (전환기 규칙)
```
규칙은 `firebase/test/build-rules.mjs` 에서 만듭니다. 규칙을 고칠 때는 두 json 을 직접 고치지 말고 이 파일을 고친 뒤 `npm run build:rules` 로 다시 만드세요.
실제 DB가 아닌 내 PC의 에뮬레이터에서만 돌아갑니다. 출력에 보이는 `permission_denied` 경고는 "막혀야 할 요청이 막혔다"는 뜻이므로 정상이며, 마지막 `fail 0` 이면 통과입니다.

## 프로그램별 교사 권한

| | 관리(수정·마감·삭제·교사 메모) | 제출자료 열람 |
|---|---|---|
| 🔒 담당자만 (교과·동아리 기본값) | 만든 교사 | 만든 교사 |
| 공통 (빛나다·심화탐구 기본값) | 만든 교사 | 모든 교사 |

- 프로그램 등록 창의 **"🔒 제출자료 열람도 담당 교사(나)만"** 체크로 정합니다.
- 학생별 모아보기에는 공통 프로그램 자료와 **내가 담당하는 비공개 프로그램 자료만** 보입니다. 출석·성적은 모든 교사가 봅니다.
- 첨부 파일도 같은 권한으로 Apps Script 가 확인한 뒤에만 내려줍니다.
- 담당 교사를 다른 교사로 넘기는 기능은 없습니다.

## ENGLISH (voca · novel 통합 로그인)

포털 로그인만으로 voca·novel에 들어갑니다. 포털 Apps Script가 각 앱 Firebase 프로젝트의 **1회용 로그인 토큰(5분)** 을 만들고, 새 탭에서 `앱주소#sso=토큰`으로 엽니다.
토큰은 학생의 **학교 Google 계정과 같은 사용자(UID)** 로 로그인시키므로, 두 앱의 승인 방식(voca 학생명단 · novel AllowedUsers)과 **기존 학습 기록은 그대로** 유지됩니다.

설정:
1. 각 Firebase 프로젝트(`wordapp-91c0a`, `novel-91d5f`) → ⚙️ 프로젝트 설정 → **서비스 계정** → **새 비공개 키 생성** → JSON 파일 받기
2. 포털 Apps Script → ⚙️ 프로젝트 설정 → **스크립트 속성**에 추가
   - `SA_VOCA` = wordapp 키 JSON 파일 내용 전체
   - `SA_NOVEL` = novel 키 JSON 파일 내용 전체
   - ⚠️ 키 파일은 비밀번호와 같습니다. 붙여넣은 뒤 받은 파일은 삭제하고, 어디에도 올리거나 공유하지 마세요.
3. `계정` 시트 J열 **학교 Google 계정**에 학생·교사의 학교 이메일 입력 → `② 계정 생성 · 정보 반영`
4. `js/config.js`의 `ENGLISH_APPS` 주소 확인 (voca·novel이 실제 배포된 주소)
5. voca·novel 쪽 승인은 예전처럼 각 앱의 명단 시트에서 합니다.

## 출결 운영 팁
- 감독교사: 출석 → 그룹 → `📷 체크인 코드·QR` 을 교실 TV/노트북에 띄우기 (코드 30분 유효, `새 코드 발급` 가능)
- 시작 시각 10분 후 체크인은 자동으로 **지각** 표시 (`js/config.js` 의 `LATE_AFTER_MINUTES`)
- 체크인 못 한 학생은 `미체크 → 결석 처리` 로 한 번에 정리, 조퇴·인정결은 버튼으로 수정하고 ✎ 로 사유 메모
- 코드는 교실 안에 있는 사람만 보이도록 띄워주세요. (코드를 친구에게 전달하는 대리 체크인은 교사 확인으로 걸러야 합니다)

## 설정 바꾸기 (`js/config.js`)
- `CATEGORIES` : 메뉴 이름·아이콘·색 (키 `bitnada/club/subject/contest` 는 데이터에 저장되므로 바꾸지 마세요)
- `ATT_STATUS` : 출결 상태 이름·색
- `EMAIL_DOMAIN`, `PW_PREFIX` : **계정을 만든 뒤에는 바꾸면 안 됩니다** (Code.gs 와 같아야 함)
